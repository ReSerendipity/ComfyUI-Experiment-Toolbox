### 0.2 实验方法：控制变量对照实验（**不是批量生成**）

本机实验一律按**控制变量法**设计，与 ComfyUI 里"批量出图"是两条不同的路线，不要混用：

| 项目 | 做法 |
|---|---|
| **提示词** | **固定为单一常量**（818 字符那一条），写进各工作流的容器控件 |
| **种子** | **固定 1111119**，写进各工作流的容器控件 |
| **变化项** | 每轮**只变一个维度**（本轮＝采样器／调度器），其余参数全部锁死 |
| **对照方式** | 每个模型以**自身官方配置**为基线，比较"相似度 + 相对指标变化"，不做跨模型绝对值比较 |
| **禁走批量路线** | 工作流子图里的 `BatchPromptReaderWithClip`（从 `input/Picture/*.txt` 读提示词）**必须旁路**。原因：① 提示词就不再受控，实验失效；② 该目录为空时直接报错。正确做法是**旁路该节点、直接注入受控提示词**，而不是往目录里塞 txt 文件 |

> 判读依据：`实践是检验真理的唯一标准`——凡是本机跑过或算过的结论，均标注证据等级与出处；未验证的说法一律留在"社区经验"档，不写进结论表。

## 三、通用经验法则



1. **以本机官方模板为最高权威**：`comfyui_workflow_templates_json\templates\` 下同名模板直接照抄即可，不必再看博客 / 二手教程。

2. **先看子图实际加载的模型文件**：文件名带 turbo/klein/distilled 是蒸馏版；不带的（z\_image\_bf16、FLUX.1-dev）按全量配。

3. **Qwen 系官方就是 euler + simple**（不是 beta；beta 是早期社区建议，官方模板未采用）。

4. **Z-Image 原生官方就是 res\_multistep + simple**（不是 euler + sgm\_uniform）。

5. **FLUX 系官方就是 euler + simple**；FLUX.2 的 Flux2Scheduler 是官方专用调度（按分辨率自适应 sigma）。

6. **2.1 的 cfg 保持 1**：官方明确 "cfg=1 时负向提示词无效，要用负向才提高 cfg"。

7. `*_gpu`**&#x20;后缀**：与非 GPU 版效果一致，仅速度 / 显存优化。

## 四、官方默认工作流的模型量化类型（DIT / CLIP / VAE 三大类）

> 以下数据取自上述 8 个官方模板 `definitions.subgraphs[].nodes` 里的真实加载节点（UNETLoader / CLIPLoader / DualCLIPLoader / VAELoader），是官方默认勾选的模型文件，非手动改过的路径。
>
> **重要前提**：所有加载节点的 `weight_dtype` / `device` 字段**均为 `default`**。即官方实现量化的方式是「直接选用预量化好的模型文件」，而不是在加载器里做运行时 dtype 转换。因此**量化类型完全体现在模型文件名后缀上**（见 4.1）。

### 4.1 量化后缀速查（文件名即量化类型）

| 文件名后缀 / 形式         | 量化类型            | 说明                                                         |
| ----------------- | --------------- | ---------------------------------------------------------- |
| `_int8_convrot`   | int8 卷积旋转量化      | Comfy-Org 推出的新型低比特量化，精度损失小、显存占用最低                            |
| `_nvfp4` / `-nvfp4-Ultra` | NVFP4（4bit 浮点，Blackwell 原生） | 比 int8/fp8 更低比特；需新架构 GPU 支持（本机 5070 Ti 可用）。本机 2512 系列实际使用此量化 |
| `_fp8_scaled`     | fp8 (e4m3fn) 带缩放 | 官方 fp8，带 per-tensor 缩放因子，质量优于裸 fp8                       |
| `_fp8_e4m3fn`     | fp8 e4m3fn 标准    | 标准 fp8，显存/速度友好，轻微质量折损                                  |
| `_bf16` / `_fp16` | 半精度（非低比特量化）     | 仍是半精度原生权重，未做 8bit 以下量化；显存比 fp32 省一半、比 fp8 略高           |
| 无后缀（如 `flux1-dev`、`flux-2-klein-4b`、`qwen_3_4b`、`clip_l`、`ae`） | 原生精度（bf16）   | 官方默认全精度分发件，通常 bf16，未做低比特量化                              |

### 4.2 三大类汇总表（官方默认选件）

| 工作流              | DIT / 扩散模型（量化）                          | CLIP / 文本编码器（量化）                                   | VAE（量化）                      |
| ---------------- | ---------------------------------------- | -------------------------------------------------- | --------------------------- |
| Qwen-Image 2.1   | `qwen_image_2.1_int8_convrot.safetensors` | `qwen3vl_8b_int8_convrot.safetensors` (type=qwen_image) | `qwen_image_2.1_vae_bf16.safetensors` (bf16) |
| Krea2 Turbo      | `krea2_turbo_fp8_scaled.safetensors`     | `qwen3vl_4b_fp8_scaled.safetensors` (type=krea2)      | `qwen_image_vae.safetensors`（标准）     |
| Flux.2 Klein     | `flux-2-klein-4b.safetensors`（原生）           | `qwen_3_4b.safetensors` (type=flux2)                | `flux2-vae.safetensors`（标准）       |
| Qwen-Image 2512  | `qwen-image-2512-nvfp4-Ultra.safetensors`（**nvfp4**） | `Qwen-image-2512-edit\qwen_2.5_vl_7b_Abliteratedte.safetensors` (type=qwen_image) | `Qwen-image-2512-edit + Krea2\qwen_image_vae.safetensors`（标准） |
| Qwen-Image（旧版）   | ⚠️ 旧版模型未下载 → 两工作流均指向 `qwen-image-2512-nvfp4-Ultra.safetensors` | 同上 | 同上 |
| Z-Image 原生       | `z_image_bf16.safetensors`（bf16 原生）         | `qwen_3_4b.safetensors` (type=lumina2)              | `ae.safetensors`（标准）             |
| Z-Image Turbo    | `z_image_turbo_bf16.safetensors`（bf16 原生）    | `qwen_3_4b.safetensors` (type=lumina2)              | `ae.safetensors`（标准）             |
| FLUX.1-dev       | `flux1-dev.safetensors`（原生）                 | `clip_l.safetensors` + `t5xxl_fp16.safetensors` (type=flux, fp16) | `ae.safetensors`（标准）             |

### 4.3 分模型说明

**DIT / 扩散模型（UNETLoader）**

* **Qwen 系走两种量化路线**：2.1 用 `int8_convrot`（最激进、最省显存）；旧版与 2512 用 `fp8_e4m3fn` / `fp8_scaled`。三者加载器 `weight_dtype` 均为 `default`，量化锁死在文件本身。
* **Krea2 Turbo** 官方给的是 `fp8_scaled`（带缩放 fp8），Turbo 蒸馏 + fp8 双省显存。
* **Flux.2 Klein** 与 **FLUX.1-dev** 官方默认**不量化**，直接发 `flux-2-klein-4b` / `flux1-dev` 原生 bf16 权重——想省显存需自己换 fp8 文件，但官方默认不换。
* **Z-Image 原生 / Turbo** 官方给的是 `bf16` 原生半精度（文件名带 `_bf16`），不是 8bit 低比特量化；相对 fp32 已省一半显存，但比 fp8/int8 占用高。

**CLIP / 文本编码器（CLIPLoader / DualCLIPLoader）**

* **Qwen 系文本编码器与 DIT 同源量化**：2.1 配 `qwen3vl_8b_int8_convrot`；旧版/2512 配 `qwen_2.5_vl_7b_fp8_scaled`；Krea2 配 `qwen3vl_4b_fp8_scaled`。
* **Flux.2 Klein / Z-Image** 共用 `qwen_3_4b.safetensors`（原生，无量化后缀），只是 `type` 不同（flux2 / lumina2）。
* **FLUX.1-dev** 是唯一的 `DualCLIPLoader`：CLIP-L（`clip_l`） + T5-XXL（`t5xxl_fp16`），T5 走 fp16，CLIP-L 为官方标准 fp16 分发件。

**VAE（VAELoader）**

* **VAE 加载器无 dtype 选择项**，官方模板一律直接选标准 VAE 文件、不做量化：`ae.safetensors`（FLUX / Z-Image 通用）、`flux2-vae.safetensors`（Flux.2）、`qwen_image_vae.safetensors`（Qwen 系标准）。
* 仅 **Qwen-Image 2.1** 例外，官方显式选了 `qwen_image_2.1_vae_bf16.safetensors`（bf16 VAE），其余 Qwen 工作流用通用的 `qwen_image_vae.safetensors`。

### 4.4 经验法则

1. **文件名后缀 = 官方量化选择**：`_int8_convrot` < `_fp8_scaled` ≈ `_fp8_e4m3fn` < `_bf16/_fp16` < 无后缀（原生）。越靠前越省显存、质量折损越大。
2. **加载器 dtype 保持 `default` 即可**：官方所有模板都没在加载器里改 dtype，改文件比改 dtype 更稳（避免 dtype 与文件不匹配报错）。
3. **想进一步省显存就换同族量化文件**：例如把 `flux1-dev.safetensors` 换成社区 fp8 版——但这是非官方路径，官方默认与原生精度绑死。
4. **VAE 基本无需量化**：官方模板统一用标准 VAE，只有 Qwen 2.1 单独指定了 bf16 VAE。

### 6.1 结论速查（重要，覆盖本文档第三节的通用法则）

| 结论 | 证据 |
|---|---|
| ⛔ **本模型不要用 `karras`** | 7 组不同采样器（euler / dpmpp_2m / dpmpp_2m_sde_gpu / dpmpp_3m_sde_gpu / dpmpp_2s_ancestral / heun / uni_pc_bh2）+ karras **全部**出现双重曝光鬼影、五官打散、发白雾化；对比度 σ 由 42 塌至 22、锐度 −64%；7 张两两相似度 **0.9991~0.9998** → 缺陷由 scheduler 决定，**与采样器无关** |
| ✅ `simple` / `beta` / `sgm_uniform` / `normal` **四者实测等价** | 两两相似度 ≥0.9976，肉眼无法区分。**不必在它们之间来回换** |
| 🏆 画质最优：`res_multistep + beta` | 锐度 228.1 vs 基线 151.3（**+51%**），五官与织物纹理最扎实，仅多耗 2 秒；次选 `res_multistep + simple`（194.8） |
| ⚠️ `euler_ancestral` / `er_sde` 会换构图 | **相同种子**下仍换场景换姿态（与基线相似度仅 0.962 / 0.949），不可用于需复刻构图的场景 |
| ⚠️ `euler_cfg_pp` 在 cfg=1 下无收益 | cfg=1 时无负向提示词，CFG++ 的引导修正无从生效（观感差异来自随机路径而非引导） |
| ℹ️ `*_gpu` 后缀不影响效果 | 只影响速度 / 显存，与对应非 GPU 版表现一致 |

### 6.2 karras 异常的根因定位（补充验证证据链）

| 验证 | 结果 | 说明 |
|---|---|---|
| `euler + karras`，steps **25 → 50** | 重影基本消失、人脸恢复清晰，仅残留一层轻雾 | 步数翻倍即可大幅恢复，说明并非调度器不可用 |
| `euler + normal`，steps=25 | 干净，与基线相似度 0.9976 | 说明"非线性调度"本身不是问题 |

> ⚠️ **本节原结论已于 2026-09-23 被 6.7 节的离线 sigma 计算推翻**：当时推断"低噪声区步数不足、去噪未走完"，但实测 karras 在 25 步下把 **14/25 步**都分给了低噪声区（σ≤0.1），是全场最多，并非不足。正确根因见 **6.7**（**高噪声区步数太少、首步跨度过大**）。

### 6.5 ⚠️ 重要：子图容器的三处取值可能互相冲突（2026-09-23 查明）

`Qwen_image.json` 里同一个「steps / cfg」有 **3 份互不相同的记录**：

| 位置 | steps | cfg | 说明 |
|---|---|---|---|
| 子图**容器**节点 `widgets_values`（positional 数组） | **8** | **1** | ⬅ **当前实际生效值**（官方 Lightning 快速路径） |
| 子图**容器**节点 `widgets_values_named`（命名字典） | 25 | 3 | 前端元数据，与 positional 不同步 |
| 子图**内部** KSampler 自身的 `widgets_values` | 50 | 4 | 被容器注入值覆盖，等于无效 |

**判定依据（代码级）**：前端设置项 `Comfy.Workflow.NamedValuesRestore`（名称 "Restore widget values by name"）为 **boolean，默认 `false`，且标记 `experimental`**。

- 设置**关**（默认）：走 legacy 位置数组 → **positional 生效**；
- 设置**开**：走命名恢复路径 → **named 生效**，positional 退化为"影子计算"、不参与应用。

本机 `user/default/comfy.settings.json` **未写入该项** → 取默认 `false` → **positional 生效**。

**操作结论**：
1. 改 steps / cfg / 采样器 / 调度器时，**先改容器节点的 positional `widgets_values`**，然后**再同步 `widgets_values_named`**（否则前端显示会不一致）；若将来把上面那个开关打开，则 named 反而成为真值——两处始终一起改最稳妥。
2. 用 headless / API 跑测时，直接读容器的 **positional** 值即为运行时真值；**不要**读子图内部 KSampler 自己的 widgets（那是被覆盖的残留值）。
3. `Qwen_image_2_1_t2i.json` 三处取值一致（25 / 1），无此问题；但注意其内部 KSampler 默认 `seed=0`、`control_after_generate=fixed`，实际种子由容器 widget 覆盖为 `1111119`；且容器 input 名为 `scheduler` 的其实是 sampler_name、`scheduler_1` 才是 scheduler，改参数时勿混淆。

### 6.6 「没有负向提示词，CFG 还要不要调到大于 1？」——理论核查

**结论：不需要。官方明确要求「没有负向提示词就保持 cfg=1」，而且 cfg=1 时负向提示词本身根本不会被使用。** 调高 CFG 的前提是「你已经写了负向提示词」，不是反过来。

#### 6.6.1 官方源原文（本机官方模板包，最高权威）

`python\Lib\site-packages\comfyui_workflow_templates_json\templates\image_qwen_image_2_1_t2i.json` 的 "Note: Usage" 里逐字写着：

```
## Parameters
- prompt: what to generate. For RGBA, see Note: transparent.
- negative_prompt: unused while cfg is 1.
- cfg: keep 1 for the Qwen Image 2.1 official path. Raise it only if you use a negative prompt.
- steps: Qwen Image 2.1 official pipeline uses about 40-50 with euler. This template starts at 25.
  More advanced samplers need fewer steps.
```

三条要点：
1. `negative_prompt: unused while cfg is 1` —— **cfg=1 时负向提示词「不被使用」**，写什么都没用。
2. `keep 1 ... Raise it only if you use a negative prompt` —— **先有负向提示词，才谈得上提高 cfg**。
3. `steps: official pipeline uses about 40-50 with euler. This template starts at 25. More advanced samplers need fewer steps.` —— 官方口径 40~50 步（euler），模板起点 25 步，**更先进的采样器需要更少步数**。这条与第六节实测完全吻合：`res_multistep` 在 25 步已优于 euler，而 `karras` 在 25 步严重欠去噪、需 50 步才恢复。

官方文档同口径（docs.comfy.org `tutorials/image/qwen/qwen-image-2-1`）：
> "All three workflows sample with `steps` 25, `cfg` 1, the `euler` sampler, and the `simple` scheduler."
（另：原生 2K，1.0 MP ≈ 1024×1024，4.0 MP = 2048×2048。）

#### 6.6.2 源码机制（为什么 cfg=1 时负向无效）

`comfy/samplers.py` → `sampling_function()`：

```python
if math.isclose(cond_scale, 1.0) and model_options.get("disable_cfg1_optimization", False) == False:
    uncond_ = None        # ← cfg=1：无条件分支直接置空
else:
    uncond_ = uncond
```

`cfg_function` 的数学形式是 `uncond + (cond - uncond) * cfg`。cfg=1 时 `uncond_=None`（`calc_cond_batch` 对 None 返回全零），结果恒等于 `cond` —— **无条件分支既不参与运算、也不做模型前向**，所以负向提示词对画面没有任何影响。（负向那段文本仍会被 `TextEncodeQwenImage21` 编码一次，但它不会被喂给扩散模型。）

#### 6.6.3 重要例外：`*_cfg_pp` 系列在 cfg=1 下仍会用到负向

源码里这几个采样器**强制**打开 `disable_cfg1_optimization=True`（即 cfg=1 也照样计算无条件分支）：

| 采样器 | 源码位置 |
|---|---|
| `euler_cfg_pp`（= `sample_euler_ancestral_cfg_pp(eta=0, s_noise=0)`） | `comfy/k_diffusion/sampling.py:1379 → 1352` |
| `euler_ancestral_cfg_pp` | 同上 `:1334 → 1352` |
| `dpmpp_2s_ancestral_cfg_pp` | `:1385 → 1398` |
| `dpmpp_2m_cfg_pp` | `:1429 → 1443` |
| `res_multistep_cfg_pp` / `res_multistep_ancestral_cfg_pp` | `:1531/:1539 → 1462（cfg_pp=True）` |
| `gradient_estimation_cfg_pp` | `:1588 → 1544（cfg_pp=True）` |

原因在 CFG++ 的实现方式（`sample_euler_ancestral_cfg_pp`）：

```python
def post_cfg_function(args):
    uncond_denoised = args["uncond_denoised"]   # 单独留存无条件分支的 x0 估计
    return args["denoised"]                     # 主路径仍用条件分支的 x0
...
d = to_d(x, sigmas[i], alpha_s * uncond_denoised)   # 噪声方向用 uncond 的 x0
x = alpha_t * denoised + sigma_down * d             # 求解走向用 cond 的 x0
```

即 CFG++ **把「条件分支的 x0」与「无条件分支的 x0」拆开分别使用**（所谓 manifold-constrained 引导），`uncond_denoised` 是这套数学的必需品，**与 cfg 数值无关**。

> **这正好解释了第六节 17 组实测里的一个现象**：`14_euler_cfg_pp + simple` 与官方基线 `01_euler + simple` 的相似度只有 **0.9882**（同调度的其余组合都 ≥0.9976），且色彩度全场最高（57.43）。原因就是 cfg_pp 在 cfg=1 时依然消费了负向条件（此处为「空字符串」的编码），而普通 `euler` 在同一 cfg 下完全不看负向。

#### 6.6.4 与 Qwen 官方 diffusers 示例的差异（易混淆点）

Qwen 官方仓库 `QwenLM/Qwen-Image` 的 diffusers 示例统一使用 **`true_cfg_scale=4.0`**，并建议不用负向时也给个空格占位：

```python
negative_prompt = " "   # Recommended if you don't use a negative prompt.
```

**不要把 `true_cfg_scale` 直接当成 ComfyUI 的 `cfg`**：那是 diffusers 那套参数体系（引导强度固定 4.0；编辑类模型另设 `guidance_scale=1.0` 关掉标准 CFG 分支）。它反映的是「**一旦启用 CFG，就必须提供无条件条件**（哪怕只是空格）」，而不是「没有负向也要把 cfg 调高」。在 ComfyUI 这条官方路径上，结论仍是 **cfg 保持 1**。

#### 6.6.5 实操建议

| 场景 | ComfyUI 的 cfg | 说明 |
|---|---|---|
| 不写负向提示词（当前 2.1 工作流的默认状态） | **保持 1** | 唯一正确选择；调高只会让「空条件」参与引导，多半更硬更饱和并抬高过曝/伪影风险 |
| 想用 CFG 抑制某些内容 | 先**写实**负向提示词，再设 1.5~2.5 | 这时 CFG 才有明确的「推离目标」 |
| 用 `*_cfg_pp` 系列 | cfg=1 也允许试 | 负向在 cfg=1 下仍被消费；若要发挥 CFG++ 的完整效果，仍需提高 cfg 并配负向 |
| 任何 cfg≠1 | 注意变慢 | cfg≠1 时每步要多算一次无条件前向（会被合并成 batch 送进模型），必然更慢；**具体慢多少本次探针时间噪声过大（40~54s，首组含加载），未能量化，不下结论** |

### 7.3 ✅ 已验证的根因：高噪声区步数太少 + 首步跨度过大

相关性极其干净：

- **σ>0.5 区间步数 ≥10 且首步 Δσ ≲0.065** → 实测全部干净（simple / sgm_uniform / beta / normal / linear_quadratic）；
- **σ>0.5 区间步数 ≤4 且首步 Δσ ≥0.188** → 实测严重重影（仅 karras）。

机制：本模型的时间轴 = σ（7.1），一阶求解器（euler）的局部截断误差 ≈ O(Δσ²)。karras 首步一次跨 Δσ = **0.1881**，是 simple（0.0205）的 **9.2 倍**，单步误差放大约 85 倍；而**前 3 步正是"定大结构"的阶段**，误差一旦把整体布局带偏，后段再精细也救不回来——这就是"双重曝光/重影"这种**全局性结构错误**（而非细节发糊）的来源。

karras 曲线出自 Karras et al. (2022)（EDM），源码 `comfy/k_diffusion/sampling.py:23 get_sigmas_karras(n, sigma_min, sigma_max, rho=7)` 只用 σ 的**两个端点**生成曲线，是为 DDPM/EDM 那种 σ∈[~0.002, ~80] 的大动态范围设计的。套到 flow 模型的 σ∈[0.0002, 1.0] 上，曲线形状完全变味：**把步数大量堆到了低噪声区（15/25），却把最需要步数的高噪声区压到只有 4 步。**

**证据链闭合**：50 步时首步 Δσ 减半到 0.0963 → 误差随之下降 → 对应实测 P1（karras@50）重影基本消失、仅剩轻雾。方向一致。

### 7.6 顺带验证掉的一条错误直觉：末步跳变大小与画质**无关**

| 调度器 | 末步前 σ → 0 | 实测 |
|---|---|---|
| `simple` | 0.0767 → 0 | ✅ 干净 |
| `linear_quadratic` | **0.1423 → 0（最大）** | ✅ 干净 |
| `normal` | 0.0004 → 0 | ✅ 干净 |
| `karras` | 0.0002 → 0（最小） | ❌ 严重重影 |

`linear_quadratic` 的末步跳变比 `simple` 大 1.9 倍，画面却同样干净；`karras` 的末步跳变全场最小，反而最差。原因在采样器实现：flow 采样器在 `sigmas[i+1] == 0` 时**直接取模型的 denoised（x0）输出、不做积分**（见 `comfy/k_diffusion/sampling.py` 中 `if sigmas[i + 1] == 0: x = denoised`），所以最后一步本身不产生截断误差。**「末步跨度大 → 没去噪完」是错误直觉。**

### 7.7 操作结论（单模型版）

1. **对 Qwen-Image 2.1**：用 σ 取值来自模型自身训练表的调度器 —— `simple` / `beta` / `sgm_uniform` / `normal` / `ddim_uniform` / `linear_quadratic`。
2. **避免 `karras`、`exponential`**（`use_ms=False`，绕过训练表并把步数错堆到低噪声区）。非要用 karras，步数至少要 x2。
3. **判断一个陌生调度器是否适配某个 flow 模型，可以先用本文方法离线算 σ 曲线**：看「高噪声区（σ>0.5σ_max）分到几步」和「首步 Δσ 占 σ_max 的百分之几」——首步 Δσ > 15% 基本可以判死，不需要真的跑图。

### 8.3 `Flux2Scheduler`（FLUX.2 官方专用）到底是什么

源码 `comfy_extras/nodes_flux.py:206`：

```python
def get_schedule(num_steps, image_seq_len):
    mu = compute_empirical_mu(image_seq_len, num_steps)      # ← 由分辨率与步数共同决定

class Flux2Scheduler:            # 输入 steps / width / height
    def execute(steps, width, height):
        seq_len = (width * height / (16 * 16))               # 1024² → 4096 tokens
        return get_schedule(steps, round(seq_len))
```

即：**先按 t 均匀取点，再用 time-snr shift 把曲线整体压缩，而 shift 的 mu 由「分辨率 + 步数」实证推算**（这正是文档里"按分辨率自适应 sigma"的含义——分辨率越高、token 越多，mu 越大，σ 曲线越向高噪声区倾斜）。它是 `simple` 的分辨率感知推广版，**不是** karras 那类绕过模型参数表的通用曲线。

1024×1024 下的实测 σ：

| steps | σ 序列 | 首步 Δσ | σ>0.5 步数 |
|---|---|---|---|
| 4 | 1.0 → 0.9674 → 0.9081 → 0.7672 → 0 | 3.3% | 4 |
| 8 | 1.0 → … → 0.5798 → 0 | 1.5% | 8 |
| 25 | 1.0 → … → 0.2671 → 0 | 0.5% | 23 |

**官方在 4 步下选的这条曲线，首步 Δσ 只有 3.3%（比同模型 `simple` 的 4.2% 还保守）**，说明官方对少步数场景是刻意"轻手轻脚"的——这从侧面印证了 8.2 的规律。

### 8.4 可直接执行的建议

1. **所有 flow 模型（Qwen / Krea2 / FLUX / FLUX.2 / Z-Image）统一避开 `karras` 与 `exponential`**，这是本次离线计算里唯一 7/7 一致的结论。
2. **少步数蒸馏模型（≤8 步）额外避开 `kl_optimal`**（Krea2-turbo / Z-Image-Turbo / FLUX.2 Klein）。
3. **安全白名单**：`simple` / `beta` / `sgm_uniform` / `normal` / `ddim_uniform` / `linear_quadratic`。
4. **换模型想省事时，先跑 `sigma_matrix.py`**：把新模型的 `sampling_settings` 填进预设表即可得到同一张风险表，无需跑图。
