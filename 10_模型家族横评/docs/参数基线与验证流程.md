## 一、四条不可协商的提示词写法

这四条是**参数层之外的变量**，一旦破坏，后续所有对照实验的结论都不可比。

### 1.1 禁否定句式

- 提示词正文里不出现 `no` / `not` / `without` / `avoid` / `nor` / `never` / `absent` /
  `lacking` / `free of`。
- **原因**：扩散/自回归 DiT 系模型（FLUX / Qwen-Image / Z-Image / Krea2）对否定句式
  训练不足，`no blur` 往往**画出 blur**——否定被当成语义 token 正面消费。
- **替代写法**：需要"排除某物"时改为正向描述。
  - ✗ `no visible dust, no sensor noise`
  - ✓ `clean warm grey background, sharp focus across the entire printed line`
- **机检**：`lib_prompt_robust.negative_hits()`；横评套件落盘前用同一正则全扫一遍，
  命中即 FAIL（不是 warning）。
- **例外**：负面提示词串本身（`prompts/NEG_real.txt`）是**另一个文件**，
  它天然全是否定词，不参与「正文零否定」这条断言；清单里用
  `is_negative_list=true` 标记以免误判。

### 1.2 禁质量后缀

- 不追加 `4K` / `8K` / `UHD` / `HDR` / `masterpiece` / `best quality` /
  `ultra HD` / `award-winning` / `highly detailed` / `professional photo`。
- **原因**：现代模型对"分辨率/质量"这类词没有梯度响应，纯挤占 token 预算；
  真实感靠**具体器材型号**（机身 + 焦段 + 光圈）而不是质量形容��。
- **允许**：风格描述词（`photorealistic`、`anime style illustration`、
  `traditional Chinese gongbi meticulous-brush painting style`）——它们描述**画面语言**，
  不是质量等级。
- **机检**：`lib_prompt_robust.quality_suffix_hits()`。

### 1.3 禁服务端扩写（prompt_extend / 提示词改写器）

- 官方 API 的 `prompt_extend` 一律 **false**；工作流里自带的
  `TextGenerate` / LLM 改写链 / `ComfySwitchNode` 选路一律剪掉。
- **原因**：本库提示词结构完整（主体 → 断言 → 空间关系 → 影调），扩写器会重排、
  合并甚至替换断言，把"眼平机位""恰好四人""引号内硬文字"这类**可验证断言**改没。
  一旦被改写，横评分数变化就无法归因到权重。
- **正负向双通道**：需要负向时走 `ConditioningZeroOut`（官方零条件口径），
  而不是塞一条真负向串；确需真负向串时单独记为链路变量并写进报告。

### 1.4 长度窗

| 语种 | 口径 | 窗 |
|---|---|---|
| 中文 | 不含空白字符数 | 500 ~ 1000 字 |
| 英文 | 词数 / 字符数双记 | 横评套件基线 150 ~ 195 词（字符 720 ~ 1000） |

- 超上限时**优先裁氛围/器材/光线从句**，不许用重复词或质量后缀凑数。
- 低于下限时补**具体细节**（空间关系、材质、动作细节），不许补形容词堆砌。
- 裁剪必须走**锚点优先**流程，见 §四。

## 二、参数基线对照

### 2.1 采样链基线（跨权重必须钉死）

横评/跑测里，以下量在**同一比较组内全部钉死**，唯一变量只能是 UNet 权重：

| 项 | 说明 |
|---|---|
| `clip_loaders` | 1 条 = `CLIPLoader`；2 条 = `DualCLIPLoader`（`clip_name1/2`） |
| `vae` / `latent_class` | VAE 文件名 / latent 节点类名（如 `EmptySD3LatentImage`） |
| `sampler` / `scheduler` / `steps` / `cfg` | 采样四要素 |
| `model_sampling` | `ModelSamplingFlux(max_shift, base_shift)` 或 `ModelSamplingAuraFlow(shift)` |
| `guidance` | `FluxGuidance(value)` |
| `negative_mode` | `zeroout` / `real` |
| `width` / `height` | 分辨率 |
| `seeds` | 种子集合 |

**模型自带默认值偏离官方模板时必须记录**。例：FLUX.2 Klein Distilled 文件自身
默认 steps 4 / cfg 1，而官方模板按 steps 20 / cfg 5 跑——这个偏离要写进报告，
否则读者会以为"cfg 5 是模板规定"。

### 2.2 两条链的实测参数（案例引用）

| 链路 | 工作流 | TE | VAE | latent | 采样 | shift/guidance | 实测耗时 |
|---|---|---|---|---|---|---|---|
| `flux1` | `flux.1-dev.json` | `clip_l` + `t5xxl_fp8_e4m3fn` | `FLUX-1-dev + ae` | `EmptySD3LatentImage` | euler / simple / 20 / cfg 1.0 | `ModelSamplingFlux(1.15, 0.5)` + `FluxGuidance 4.0` | — |
| `flux2klein` | `Flux.2_Klein-9B-Distilled.json` | `qwen_3_8b_fp8mixed`(flux2) | `flux2-vae` | `EmptyFlux2LatentImage` | euler / `Flux2Scheduler` / 20 / cfg 5.0 | 无 | — |
| `zimage` | `Z_image.json` | `qwen_3_4b_fp8_mixed`(lumina2) | `FLUX-1-dev + ae` | `EmptySD3LatentImage` | `res_multistep` / simple / 25 / cfg 4.0 | shift 3.0（ZImage 模型配置内建） | **86.5 s**（25 步，含 5.37 GB TE 冷载入） |

### 2.3 长度与尺寸基线

| 维度 | 基线 |
|---|---|
| 方图 | 1024×1024 |
| 竖版 | 832×1216（或 1536×2688 的官方 API 档） |
| 横版 | 1216×832（或 2688×1536） |
| 方版 API 档 | 2048×2048 |

## 三、验证流程（迭代纪律）

1. **固定 seed 迭代法**：同一 seed 下多次生成，**只改文字**才能归因对比。
   seed 变了之后所有像素差异都无法归因。
2. **单变量原则**：一次只改一处（一个短语 / 一个参数），否则无法定位因果。
3. **seed 不进结论**：seed 是会话级参数，调优结论只回填文字写法或参数表，
   不写进"某个 seed 下更好"。
4. **同 seed 复跑应字节一致**：确定性正常；不一致说明链路里有非确定性源
   （随机节点、缓存命中差异），先查清再继续。
5. **确定性回填**：每条提示词落盘时记 `sha256`，台账里逐字节对账，
   保证"同一条提示词"在任何一次跑测里真的是同一条。
6. **输出规格基线**：photorealistic、写实单张、构图断言显式写进正文。
7. **失败模式必须回流**：出现新失败模式就补进案例库（症状 → 根因 → 修法），
   通用规律升级成硬规则并加机检；**不许只在报告里写一句"注意 X"**。
8. **从源头修**：提示词层的问题在生成端修（引擎/工作流），不要在输出文件里手改。

## 四、精简裁剪的锚点优先流程

超长度窗要裁时，**不许按位置截断**（截半句会产生病句）。按语义单元裁，顺序：

1. 切子句（`,` `;` `.` 为界）。
2. 给每个子句打**锚点**标签：
   - `hard_literal`：引号包裹的硬文字（如 `"NORTHWIND 1974"`）——**绝不可删**
   - `count`：显式计数（`exactly four people`、`four plates`）
   - `angle`：机位/视角/景别（`eye-level`、`low camera angle`、`three-quarter`、
     `worm's-eye`、`frontal`、`from behind`）
   - `spatial`：空间关系（`to the left of`、`flanked`、`on the same line`、
     `inside the frame`）
   - `subject` / `action`：人物外貌与动作（弱锚点）
3. 删减规则分两档：
   - **override**（器材 / 光线修饰 / 影调 / 画质后缀 / 大气颗粒 / 景深光圈）
     ——可压过 `subject` / `action` 这类弱锚点；
   - **weak**（空泛背景 / 负空间之类）——只在锚点为空时才删。
4. 强锚点命中即免删；`override` 规则命中且无强锚点 → 删。
5. 重组时统一断句规整：句号后补空格、去重逗号、结尾补句号。

工具实现见同目录 `../lib_prompt_robust.py` 的 `slimify()` / `assert_anchor_retention()`。

**自测结果（S1，2026-10）**：

```
chars 889 -> 705 (79.3%)   words 168 -> 126   子句 22 -> 16（删 6）
删：light_mod ×2 / optics ×2 / grade ×1 / atmosphere ×1
锚点 full = action,angle,count,spatial,subject
锚点 slim = action,angle,count,spatial,subject   → 全部保留
```

**收益**：这条探针回答的是"权重排名是否被长度撑着"。若精简版重跑后排名不变，
说明 S1–S9 的分数不依赖器材堆料；若排名变了，**所有横评结论必须附长度说明**。
本库当前只产计划（`plan_pairs`），不出图——出图需另行接线并遵守 §三 全纪律。

## 五、验证案例引用：216 张全正向矩阵

作为本文四条写法 + 单变量纪律的**实证**，工具箱 `10_模型家族横评` 首轮跑测：

- 矩阵：`8 权重 × S1–S9 × 3 seeds = 216` 张，评分表 216 行、216 个唯一 `file`，
  无缺漏无重复。
- 编写约束（9 条全部机检通过）：
  - 全英文；全正向描述、**零否定词**
    （正则扫 `no|not|without|avoid|nor|never|absent` → 全部 NONE）；
  - **零质量后缀**（扫 `4k|8k|uhd|hdr|masterpiece|best quality|ultra hd` → 全部 NONE）；
  - 篇幅 150–195 词（全部 ≥80）；
  - 每条都把机位/角度/景别写成**可验证断言**（硬门逐项 PASS/FAIL 记账）。
- 结论侧的纪律同样重要：
  - 家族内统计必须**同时给「含例外权重 / 不含例外权重」两版**；
  - 跨链路例外权重单列一个分层，**不得**把它的差异表述成"同链路权重差异"；
  - 跨种子相似度只在**同模型同 prompt**口径下用，跨架构/跨家族像素不可比。
