# 场景断言审计法

> 定位：**项目无关**的「如何机审提示词断言与题材一致性」。输入一组提示词 + 一组题材标签
> + 一组候选素材池，输出逐件的判定分层与池级卫生报告。**全程只读**。
>
> 思路来源：`Picture/tools/scene_consistency_audit.py` 的 phrase×theme 二元判定体系
> （Jaccard 距离 + 分层归因 + 跨类串味最严重档 + 池级跨类歧义统计）。
> 那边的题材取自文件名最后一段、场景短语取自正文首个"场景"段；本文把它抽象成
> 「断言 × 题材」的一致性审计，并保留它的分层归因骨架。

---

## 一、要抓的病

一句话：**提示词正文里的场景断言与它声明的题材自相矛盾**。

真实翻车形态（均为实测）：

- 题材写"烟花台前"，正文场景断言落在"卡丁车赛道"；
- 题材写"步行街漫步"，正文场景断言落在"直升机舱内"；
- 题材写"落地镜前"，正文场景断言落在"无镜面的户外空地"（漏写反射实体）。

这类矛盾**直接拉垮画面**，且读图人往往只会打低分而说不清原因——所以必须在
出图之前用机器抓出来。

---

## 二、判定输入三件套

| 输入 | 含义 | 抽取方式（案例） |
|---|---|---|
| **theme**（题材标签） | 这条提示词声明的场景题材 | 从文件名的题材段取（那边是文件名最后一段） |
| **phrase**（场景断言） | 正文实际写出的场景短语 | 正文首个「场景」标记之后、到第一个逗号或句号为止 |
| **pool**（候选池） | 各题材/类目下允许出现的场景条目集合 | 素材池按类目分组 |

外加一个可选输入：**保护词集合**（引擎对该题材实际生效的位置约束）。
它的作用是区分「门本该拦住却没拦住」和「门本来就管不到」——见 §四。

---

## 三、判定分层（核心）

按顺序判，命中即停：

| 层 | 名称 | 判据 | 严重度 |
|---|---|---|---|
| 0 | `no_assertion` | 正文抽不出场景断言 | 中（信息缺失） |
| 0b | `malformed_assertion` | 抽出的短语含拼接符（如 `A + B + C`）或明显破损 | 中 |
| 1 | `exact` | phrase 与 theme 字面同源（相等或互含） | ✅ 通过 |
| 2 | `gate_ok` | phrase 命中引擎现行两层保护（互斥桶 / 固定地点词兜底） | ✅ 通过 |
| 3 | `T2_near` / `T2_far` | phrase 属**本类目池**另一条目，且题材有约束（门应拦未拦） | ⚠️ / ❌ |
| 4 | `T3_near` / `T3_far` | phrase 属本类目池另一条目，且题材**无**约束（保护盲抽区） | ⚠️ / ❌ |
| 5 | `T1_crosscat` | phrase **只**出现在其他类目池（跨类串味） | ❌❌ 最严重 |
| 6 | `offpool_other` | phrase 不在任何场景池（自由句 / 手工件） | 交人工抽查 |

### 3.1 为什么 T1 最严重

- T2/T3 是**同类目内错位**：画面还是这个类目的空间，只是具体地点不对，
  观感是"跑偏"。
- T1 是**跨类目串味**：空间类型整体换了（把摄影棚内景抽成赛道、把室内抽成
  户外空地）。这类图往往连"题材"都不成立，评分里体现为"这张图我没看懂在拍什么"。

### 3.2 T2 vs T3 的分界：门到底管不管得到

这一层是整套方法最有价值的部分——它把"内容错了"细分成"**门失职**"和
"**门没负责**"：

- 题材**有**位置约束（引擎能算出必须出现的地点词），但 phrase 没命中
  → `T2`：**门应拦未拦，是 bug**，优先级最高。
- 题材**无**位置约束（类目池盲抽区），phrase 只是同池另一条目
  → `T3`：**是既有设计的盲区**，要么加约束，要么接受。

同理，"第二层兜底"（短词 + 固定地点词）只在**类目池内确实存在命中条目**时才算真生效，
否则等同盲抽区，必须降级到 T3 判——**不要把名义保护当成实际保护**。

## 四、near / far 的距离度量

### 4.1 二元组 Jaccard

```
bigrams(s) = { s[i:i+2] for i in range(len(s)-1) }     # 字符二元组
J(a, b)   = |A ∩ B| / |A ∪ B|
near 当且仅当 J >= 阈值
```

**为什么用二元组而不是整词**：短题材串（"咖啡" vs "咖啡厅"）整词 Jaccard 恒为 0，
会被误判成 far；二元组能捕捉"后缀共享"。同义归一（如 `渡轮→轮渡`、`烟火→烟花`）
要在**算 J 之前**做，且只用于距离判定，不改写原文。

### 4.2 阈值取值：案例参数与一处必须记录的漂移

| 出处 | 阈值 |
|---|---|
| `scene_consistency_audit.py` 模块 docstring 写的 | **0.34** |
| 同一文件 `near_far()` 代码里的实际判据 | **0.20** |
| 同场馆前缀规则（`KTV`/`机场`/`博物馆`/`图书馆`/`书店`/`酒吧`/`网吧`/`医院`/`商场`/`校园`/`健身房`/`咖啡厅`/`游乐园`/`邮轮`/`地铁`/`高铁`/`渡轮`/`公车`/`出租车`） | 双方同前缀且不相等 → 直接判 near（"异地同场算近义微差"，如 `KTV包厢` vs `KTV走廊`） |

> **这是从源项目抄下来的第一手教训**：文档里写的阈值和代码里生效的阈值不一致，
> 而报告里所有 near/far 百分比都是按**代码值**算的。移植这套方法时，
> 阈值必须**在代码里定义一次并被文档引用**，不要在两处各写一个数。
> 另外，同场馆前缀白名单是**硬规则**，优先于 Jaccard——先查白名单再算距离。

### 4.3 阈值调参建议

| 场景 | 建议阈值 | 理由 |
|---|---|---|
| 中文长题材串（≥6 字） | 0.25 ~ 0.35 | 二元组基数大，轻微改动就掉相似度 |
| 中文短题材串（2~4 字） | 0.15 ~ 0.20 | 基数小，阈值高会全判 far |
| 英文题材串 | 0.30 ~ 0.40 | 词级差异更大，需更高阈值 |
| 有同场馆白名单 | 白名单优先，阈值可放宽 | 白名单已覆盖高频近义对 |

## 五、机审的四个输出

1. **逐件明细**：`(条目, 题材, 断言短语, 判定层, 保护词, 池归属类目, 落盘日期)`
   → JSON，供后续逐条修。
2. **分层统计**：各层件数与百分比，按 `exact → gate_ok → T2/T3 → T1 → offpool` 顺序
   列出；矛盾件合计率 + 其中 far/near 拆分。
3. **矛盾件按类目 × 层**交叉表**：定位"哪个类目的门最容易失职"。
4. **池级卫生报告**：**跨类歧义条目**——同一条目同时出现在 ≥2 个类目池。
   这些条目天生会引发 T1 串味，是素材池的债：
   ```
   key(条目的首个逗号段) -> {出现在哪些类目池}
   len(类目数) >= 2  =>  歧义条目
   ```

> 第 4 项的价值远高于前 3 项：前 3 项是"这次错了多少"，第 4 项是"下次还会错在哪"。
> 修完素材池，T1 会整体下降，而不是逐条打补丁。

## 六、执行纪律

1. **只读**。审计脚本不许生成、不许改提示词库、不许碰任何台账。
   （源项目明确写了这条，理由是审计结果要能被别人复现。）
2. **缺锚记 issue，不静默补齐**。补出来的"合格"是假合格。
3. **保护词要区分名义与实际**（§3.2），报告里把"名义保护/实际保护"两列都给。
4. **无法机判的进人工抽查队列**（`offpool_other`），不要硬塞进某个层。
5. **判定规则与阈值写在代码里，文档只引用**（§4.2 的教训）。
6. **修复顺序**：先修池级歧义（治本）→ 再补题材约束（治门）→ 最后逐条手改（治标）。

## 七、移植到「角度/机位断言」维度的扩展

同一套骨架可以横向搬到机位断言上（横评提示词套件正好需要）：

| 概念 | 场景断言版 | 机位断言版 |
|---|---|---|
| theme（声明） | 题材/类目 | **声明的机位与景别** |
| phrase（实际） | 正文场景短语 | 正文里实际出现的机位短语 |
| pool（候选池） | 类目 → 场景条目池 | 机位枚举 → 同义词集合 |
| T1_crosscat | 跨类目串味 | **机位族互斥冲突**（如同时写 `eye-level` 与 `worm's-eye`，或声明低角度却写 `eye-level camera`） |
| T2 vs T3 | 门失职 vs 盲区 | 断言写了但与声明互斥（失职）vs 根本没写机位断言（盲区） |
| near/far | 二元组 Jaccard | 机位族前缀规则（`low` / `high` / `eye` / `three-quarter` …）+ Jaccard |

**这一步的价值**：机位断言是横评里最容易被"提示词写得含糊"污染的维度。
一旦某条提示词里同时出现两个互斥机位族词，**这条的所有分数都要作废**——
因为不同读图人会按不同机位理解，打分不可比。这类检查必须在出图**之前**做，成本几乎为零。
