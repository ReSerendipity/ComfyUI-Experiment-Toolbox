## 二、缺口清单（每条均有实测事实支撑）

| # | 缺口 | 实测依据 |
|---|---|---|
| G1 | 视频零质检：h3dur 跑出的 5 档视频目前只能人眼看 | ffmpeg/ffprobe 全仓零调用；fiqc（lib_image_qc_enh.py）纯像素统计只吃图像 |
| G2 | 显存边界靠手工标定，OOM 无自动兜底 | 10s/11s/15s 直接 OOM（峰值 12.15~12.24GB > 11.91GB）后人工降分辨率重跑；`expandable_segments` 对真实容量不足无效（已实测） |

| G8 | 提示词三层（素材/质检/鲁棒性）缺跑测闭环 | fkit 出素材、fpqc 检提交、frobust 出计划，但没有「变体矩阵→跑测→自动质检」的串联消费 |

## 三、扩展项设计（E1~E8）

### E1 · 视频质检库 `vqc`（P0，补 G1）

- **形态**：新增 `10_模型家族横评/lib_video_qc.py`，入口 `run.py vqc`（对标 fiqc，只读不出图）
- **能力**：
  - 容器层：ffprobe 校验时长/帧率/分辨率/视频轨编码/音频轨（存在性+编码+采样率+声道）
  - 帧层：等间隔抽帧 → 黑帧（均值近 0）/冻结帧（与上一帧差近 0）/过曝帧统计
  - 时序代理指标：相邻帧差直方图（抖动/突变检测，无需光流重依赖）
- **边界遵守**：ffmpeg/ffprobe 走子进程调用（本机 ComfyUI 环境已含 ffmpeg），**不引入任何 pip 依赖**；放在 10 轨与 Gate ⑥（10 只准 import 01）兼容——本模块零 import，纯文件消费
- **验收**：对 `03_受控跑测/h3_duration_logs` 已产出的 5 档视频跑 vqc，输出每档帧率=24、时长命中（5.17/8.00/10.13/11.54/15.08s）、音频轨=aac 32kHz 立体声，与人工已知结论逐项交叉一致；对合成坏样本（抽掉音频轨/注入黑帧）必须 FAIL 并指明维度

### E2 · 显存自适应调度 + OOM 自动降档（P0，补 G2）

- **形态**：`03_受控跑测/lib_vram.py`（同轨库，Gate ⑥ 放行）+ `run_h3_durations.py` 接入
- **能力**：
  - 跑测前读 `nvidia-smi --query-gpu=memory.used,memory.total` 推算可用显存，从边界矩阵自动选起始档（本机标定值 11.91GB 作为默认基线，支持 `--vram-budget` 覆盖）
  - 提交后捕获 OOM 特征（history 里 execution error 含 out of memory / CUDA out of memory）→ 自动降一档分辨率重交 → 记录 fallback 轨迹进 JSONL（原始档位 + 降档原因 + 实际档位）
  - 降到底档仍失败才终止，exit code 区分「全部成功 / 部分降档 / 失败」
- **验收**：构造必 OOM 组合（15s @ 1344×768）→ 自动降档链 1344×768→1152×640→960×544，最终在 960×544 出片，JSONL 里有完整 fallback 轨迹；正常档位（5s@1344×768）零降档直通

### E3 · `run.py full` 一键全链流水线（P0，补 G7）

- **形态**：仅改根入口 `run.py`（加 FULL 列表），零新逻辑——所有环节均已实跑验证
- **链路**：`flatten 验证 → fgate check → fbench --dry-run → fbench 实跑 → fanalyze → fverify → fiqc → vqc（E1 就绪后）`
- **语义**：默认 dry-run 全链只读；`--apply` 才实跑；任一步非零退出即中断并报告断点（沿用 pipeline 现有中断范式）
- **验收**：`python run.py full --dry-run` 0 提交打印全链计划；实跑一次 exit 0 且每环产物落盘

### E4 · 档位跑测框架化：h3dur → 多模型适配器（P1，补 G3）

- **形态**：新增 `03_受控跑测/run_durations.py`（通用档位跑测器）+ `03_受控跑测/adapters.json`（模型适配配置）；`run_h3_durations.py` 保留为 H3 特化壳（薄封装，行为不变，防回归）
- **适配器字段**：工作流路径 / 时长节点 ID / 帧数换算式（`17k+5@24fps`、`8k+1@16fps` 等可注册）/ 档位矩阵（时长×分辨率）/ 可选覆盖点（TE/DiT/LoRA 节点 ID）
- **能力**：新增一个视频模型 = 在 adapters.json 加一条，跑测器本体零改动；`--adapter <name>` 选择
- **验收**：以 H3 适配器跑 `--dry-run`，计划与现有 h3dur 输出逐字段一致（回归等价）；再造一个合成 adapter（帧数换算用 8k+1）验证换算式可插拔

### E5 · 历史趋势回归 `ftrend`（P1，补 G4）

- **形态**：新增 `10_模型家族横评/trend_family.py`，入口 `run.py ftrend`（只读）
- **能力**：消费 `03_受控跑测/*/result_log.jsonl` 与横评 ledger（**纯文件读取，零跨轨 import**，Gate ⑥ 兼容）；输出「同一对象（家族权重/档位/提示词哈希）跨日期」的指标曲线与评分表 diff；自动标红回归项（本次差于上次超过阈值）
- **验收**：对现存两次 fbench 的 ledger（models 20/20 两次全量跑测）生成趋势报告，能正确标出「无回归」；注入一组合成回归数据（改低某权重评分）必须被标红

### E6 · fgate 扩展：重复量化检测 + 孤儿文件检测（P1，补 G5）

- **形态**：扩 `10_模型家族横评/lib_inventory_gate.py` 两个检测维度 + CI Gate ③ 的 synthetic selftest 同步扩两步
- **能力**：
  - 重复量化：同目录同 stem、不同量化后缀（int8/fp8/fp4/bf16…）→ 报告（允许白名单豁免，因为 Z-image 双量化是刻意保留项）
  - 孤儿文件：磁盘上的模型文件不被任何 tracked 工作流 JSON 引用 → 只读报告（不删，删不归工具箱管）
- **验收**：合成 fixture 构造「同 stem 双量化」+「无引用孤儿」，`fgate check` 必须 FAIL 且逐条指明维度；对当前本机 models 目录跑一遍，输出与 2026-10-15 手工审计结论一致（2 处真重复被点名、白名单项不误报）

### E7 · 面板扩展：视频档位跑测页 + 跑测实时进度（P1，补 G6）

- **形态**：扩 `09_Web面板/panel.py` + `index.html`（子进程转发 `run.py h3dur` / `fbench`，**不 import 03/10 模块**，Gate ⑥ 兼容）；进度用轮询读 JSONL 行数（不上 SSE，保持零依赖）
- **能力**：新增「视频档位」页：选 adapter（E4 就绪后）/选档位/选 TE-DiT 覆盖 → 发起 → 实时显示已完成档位与 fallback 轨迹（E2 的 JSONL 字段直接渲染）；顶栏加 ComfyUI 状态徽章（已有 comfy_status 复用）
- **验收**：浏览器发起 5s 档跑测，页面实时滚动到完成；`tests/test_panel_api.py` 扩用例覆盖新路由；CI Gate ⑦ 通过

### E8 · 提示词变体闭环（P2，补 G8）

- **形态**：`10_模型家族横评/` 内扩 `lib_sfw_prompts_kit.py`：变体矩阵生成（主体×风格×构图笛卡尔积，类目白名单不变）→ 交 fbench 跑测 → 跑完自动过 fpqc + 新「首轮淘汰」规则（同一提示词全家族产出均触发 QC 失败即淘汰该提示词）
- **验收**：对一个小家族（≤4 权重）× 8 条变体提示词实跑，产出「提示词淘汰名单 + 存活提示词的家族评分表」

## 四、优先级与批次（P0→P2，按依赖排序）

| 批次 | 项 | 补的缺口 | 依赖 | 自检 |
|---|---|---|---|---|
| **批 1** | E1 vqc | G1 | 无 | 对 5 档实产视频交叉验证 + 合成坏样本 FAIL |
| **批 1** | E2 显存自适应 | G2 | 无 | 15s@1344×768 必 OOM 场景自动降档出片 |
| **批 1** | E3 full 流水线 | G7 | 无（E1 就绪前链路自动跳过 vqc 环） | dry-run 0 提交 + 实跑 exit 0 |
| **批 2** | E4 适配器框架 | G3 | E2（共用降档逻辑） | H3 回归等价 + 合成 adapter 换算式可插拔 |
| **批 2** | E5 ftrend | G4 | 无 | 两次存量 ledger 出趋势 + 合成回归标红 |
| **批 2** | E6 fgate 扩展 | G5 | 无 | 合成 fixture FAIL + 本机审计结论复现 |
| **批 2** | E7 面板扩展 | G6 | E1/E2（页面渲染其产物） | 浏览器实跑 + test_panel_api 扩用例 |
| **批 3** | E8 提示词闭环 | G8 | E4/E5 | 小家族×8 变体实跑 |

**明确不做**（记录决策，防范围蔓延）：
- backup 统一库——目前只有 `unify --apply` 与 05 结构轨脚本两个写盘点，各自本地备份已是验证过的范式，抽象共享库收益低于成本
- 多 ComfyUI 版本并行跑测——本机只有 aki-v3.2 一个实例在跑，v3 旧实例已停；等真有双实例需求再做（届时只需给 COMFY 常量加 `--base-url`）
- SSE/WebSocket 实时推送——轮询 JSONL 对分钟级跑测足够，零依赖红线优先

## 五、实施时的同步动作（每批）

1. `run.py` ENTRIES 注册新入口 + 根 README 目录树/命令示例同步
2. 新模块按 Gate ⑥ 依赖方向落位（见各项「边界遵守」）
3. 新增 CI 门禁或扩 selftest（E1/E5/E6 各有 synthetic selftest 步；E7 扩 tests/）
4. AGENTS.md 公开仓红线不破：无本机绝对路径（%USERPROFILE% 运行时展开）、ffmpeg 路径用 `shutil.which` 探测
5. 每批一个 commit，附证据链（实跑输出），**不 push**（双分支红线）
